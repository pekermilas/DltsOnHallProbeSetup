Triggered acquisitions put a time axis in the tick-stamp channels

The evaluation, the writer and the first 58 tests assumed tickStampImps holds 60 MHz clock ticks. The triggered pull_data() path that runs use stores the DAQ grid's time axis there instead: float seconds, 0 to 4.89 s. The writer cast those channels to uint64, which truncates every value to 0 through 4. cleanup_data() uses that channel to drop samples and rebuild timeStampImps, so analysis of a real HDF5 run would have diverged from the JSON run. Reproduced first on the 23 Sep JSON run: both tick-stamp channels collapsed to 2 distinct values.

Fixed before the run

zurichInstruments_Control.writeDataH5() stores tick stamps as uint64 only when they arrive as integers, and as lossless float64 otherwise. Regression tests use the triggered data shape (writer round trip, JSON-equivalent cleanup, converter).

Extract & Average found no pulses at the GUI's default pulse levels

liveDataTab._compute_legacy_transients() located fill pulses with a fixed test, AuxInput1 > -2.5 V, which suits 0 / −5 V pulses. The GUI-default Aux settings give −0.5 / −1.5 V, which never cross −2.5 V, so Qualitative Extract & Average and Detailed Analysis silently skipped every file, JSON and HDF5 alike, and the Qualitative plot stayed empty. The Timing Boundaries also kept their 500 ms default although this run's reverse bias is 6 ms, and the plot's "pF" axis showed values in the millions with no unit scaling.

Fixed after the run; this report uses the fixed code

The pulse search now puts its threshold midway between each file's own two excitation levels (−2.5 V for 0 / −5 V pulses, so the 47 files of the 23 Sep run give identical transients to before; −1.0 V here). A file with no pulses, or none followed by a full reverse-bias window, is reported in the log with the reason instead of being skipped silently, and the plot says so. Loading a run folder fills Timing Boundaries from its runParams.txt (State Enable Time = reverse bias, State Disable Time = fill). The plot scales its axis to pF, nF, µF or mF and no longer uses offset notation.

Live Tools emissions had a time axis near 10−11 s

impdData.cleanup_data() treated the triggered time axis's genuine first sample (t = 0 s) as a missing clock tick. It replaced it using a step of int(1.87e-5) = 0, which falls back to 1, giving −1 s, and then divided the whole axis by 60 MHz. Emission plots in Live Tools and the time axis Quick Analysis takes from them came out on a ~10−11 s scale, for JSON and HDF5 runs alike.

Fixed after the run; this report uses the fixed code

cleanup_data() recognises a time axis in seconds (float, non-integral) and keeps it in seconds, with its t = 0 origin. Integer clock ticks are handled exactly as before. The test suite was 88/88 passing at that point.

Found in the review after the run: run folder, serial link, gaps and temperatures

An empty Data Root Folder gave init_experiment() the path \MMDDYY\HHMMSS\, a run folder at the root of the current drive; a relative one landed wherever the GUI was started. A controller that stopped answering made mK2000B.read_temp() wait forever, which hangs a run. impdData._gap_remove() shifted one segment by the wrong offset and did not handle the backward jump an appended record produces. Temperatures parsed from step-file and ZI history names were int(T) + 273: decimals dropped (25.5 °C read as 298 K) and 273 instead of 273.15.

Fixed; this report uses the fixed code

init_experiment() refuses an empty or relative root folder and builds Root\MMDDYY\HHMMSS\ with os.path.join. The serial port has a 2 s timeout; read_temp() retries a missed reply once and then raises TimeoutError (lock released), so go_to_temp() fails instead of hanging. _gap_remove() handles forward gaps, backward jumps and several gaps, on tick and seconds axes. Temperature keys are exact kelvin (T + 273.15, decimals kept), rounded to 10−6 K.

Found in the review after the run: edge peaks broke both Arrhenius fits

When a window's signal is still rising at the edge of the peak search range, the spline peak finder puts the peak on the last grid point in every bootstrap sample and reports an error of about 10−13 K. That point then dominated the error-weighted Arrhenius fit. On the 23 Sep run (47 temperatures) Detailed Analysis with its GUI-default windows gave Et = 90.967 eV, and Quick Analysis with its defaults gave 1.519 eV with an error of 6×1010 eV. The two tabs also normalized, skipped and fitted differently, so they disagreed even on good data.

Fixed; section 06 uses the fixed code

A peak on the edge of the search range, or with an error below 10−4 K, keeps its T_peak but loses its error, and that window is left out of the fit (all windows are fitted unweighted only if fewer than 3 have errors). Quick Analysis now calls Detailed Analysis' own functions for C∞ (mean over 40–90 % of the reverse bias), S(T), the peak, the fit and Nt, and both tabs share default windows, search range, γ, Nd and kB. On the 23 Sep run: Detailed Analysis defaults 0.693 ± 0.013 eV; Quick Analysis defaults 0.708 ± 0.009 eV (two edge windows excluded); with windows suited to the data both tabs give 0.677 ± 0.007 eV, σ = 3.02×10−14 cm², Nt = 1.34×1013 cm−3. The test suite is 163/163 passing.
