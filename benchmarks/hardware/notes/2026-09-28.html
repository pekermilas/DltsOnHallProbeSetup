Triggered acquisitions put a time axis in the tick-stamp channels

The evaluation, the writer and the first 58 tests assumed tickStampImps holds 60 MHz clock ticks. The triggered pull_data() path that runs use stores the DAQ grid's time axis there instead: float seconds, 0 to 4.89 s. The writer cast those channels to uint64, which truncates every value to 0 through 4. cleanup_data() uses that channel to drop samples and rebuild timeStampImps, so analysis of a real HDF5 run would have diverged from the JSON run. Reproduced first on the 23 Sep JSON run: both tick-stamp channels collapsed to 2 distinct values.

Fixed before the run

zurichInstruments_Control.writeDataH5() stores tick stamps as uint64 only when they arrive as integers, and as lossless float64 otherwise. Regression tests use the triggered data shape (writer round trip, JSON-equivalent cleanup, converter).

Extract & Average found no pulses at the GUI's default pulse levels

liveDataTab._compute_legacy_transients() located fill pulses with a fixed test, AuxInput1 > -2.5 V, which suits 0 / −5 V pulses. The GUI-default Aux settings give −0.5 / −1.5 V, which never cross −2.5 V, so Qualitative Extract & Average and Detailed Analysis silently skipped every file, JSON and HDF5 alike, and the Qualitative plot stayed empty. The Timing Boundaries also kept their 500 ms default although this run's reverse bias is 6 ms, and the plot's "pF" axis showed values in the millions with no unit scaling.

Fixed after the run; this report uses the fixed code

The pulse search now puts its threshold midway between each file's own two excitation levels (−2.5 V for 0 / −5 V pulses, so the 47 files of the 23 Sep run give identical transients to before; −1.0 V here). A file with no pulses, or none followed by a full reverse-bias window, is reported in the log with the reason instead of being skipped silently, and the plot says so. Loading a run folder fills Timing Boundaries from its runParams.txt (State Enable Time = reverse bias, State Disable Time = fill). The plot scales its axis to pF, nF, µF or mF and no longer uses offset notation.

Live Tools emissions had a time axis near 10−11 s

impdData.cleanup_data() treated the triggered time axis's genuine first sample (t = 0 s) as a missing clock tick. It replaced it using a step of int(1.87e-5) = 0, which falls back to 1, giving −1 s, and then divided the whole axis by 60 MHz. Emission plots in Live Tools and the time axis Quick Analysis takes from them came out on a ~10−11 s scale, for JSON and HDF5 runs alike.

Fixed after the run; this report uses the fixed code

cleanup_data() recognises a time axis in seconds (float, non-integral) and keeps it in seconds, with its t = 0 origin. Integer clock ticks are handled exactly as before. The test suite is 88/88 passing.
